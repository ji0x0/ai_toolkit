# 업무 구현과 코드 이해 운영

실제 업무의 시작/마감·첫 인계·보완 종료·이해 구간을 [시간 기준](../.agents/skills/solve-task/references/time-budget.md)에 따라 정한다. 개인 시간표는 사용자 지시로 전달한다.

| 구간 | 진행 |
| --- | --- |
| 문제 분석·1차 구현 | 필요한 질문/답변, 상세 브리핑 확인, 필수 기능·대표 검증과 읽을 자료 인계 |
| 보완과 이해 병행 | 합의한 수정·영향 검사·코드/주석/설명 정합, 사용자 직접 확인 |
| 변경 없는 이해 | 현재 코드·준비된 자료·기존 검사 결과로 예측/추적/본인 설명 |

첫 인계가 늦어져도 마지막 구간을 자동으로 개발에 쓰지 않는다. 발견한 오류는 수정 후보로 남기고 명시 수정 요청이 있으면 이해 시간 영향을 설명한다.

## 구현 전과 작업 중

[브리핑 기준](../.agents/skills/solve-task/references/implementation-brief.md)으로 결과물·사용 흐름·기능/예외·구조·대안·검증·시간을 설명한다. 새 계획에 대한 확인 뒤 구현하고, 같은 범위의 통상 구현/검사/수정은 재승인받지 않는다. 중요한 범위·정책·계약·구조·일정 변경만 다시 설명한다.

기존 스택/작은 경로를 우선한다. 전체 예시 앱 대신 필요한 모듈·코드만 채택하고 변경한 부분만 이해 대상으로 연결한다. 시작 시 모든 참고 문서를 읽지 않는다.

## 실제 코드 읽기

사용자/문제와 예상 결과→유스케이스/사용 흐름→아키텍처/라우팅→모듈 입출력→핵심 함수/주석→검사 결과→선택 이유/한계 순서로 읽는다. [코드 이해 기준](../.agents/skills/build-service/references/code-understanding.md)에 따라 작은 입력의 중간 값을 추적한다. 기술 이름/그림만으로 이해 완료라고 하지 않는다.

[테스트 설명](../.agents/skills/verify-result/references/test-explanation.md)은 목적·입력·기대값과 근거·실제 결과·판정·범위를 연결한다. 검사기에는 고의 규칙 위반을 넣어 검출 여부도 확인한다. 최적화·배경 작업·민감도는 실제 기능일 때만 다룬다.

## 문서는 정본과 변경 구획만

- SERVICE.md: 현재 구조·계약·실행/운영·테스트 상세·읽는 지도.
- probe.md: 문제/사용자·원인 근거·선택/대안·핵심 검증·한계.
- devlog.md: 실제 질의응답·결정·실패/수정·명령/결과 사건.

긴 설계/로그를 중복 복제하지 않는다. 변동 없는 설명 턴에는 문서를 다시 쓰지 않으며 이해 구간에는 기존 자료를 쓴다. 실제 사용자의 설명/직접 확인이 있을 때만 그 범위를 짧게 기록한다.
