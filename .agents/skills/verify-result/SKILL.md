# 검증 근거를 읽고 설명하기

[테스트 설명 기준](references/test-explanation.md)을 사용한다. 실행 전 목적·입력/기대값·방법, 실행 후 실제 결과·판정·범위/한계를 쉬운 한국어로 설명한다. 테스트 코드의 준비·호출·assert와 실행 출력을 대조하며 개수/종료 코드만 보고하지 않는다.

## 중요한 주장부터 확인

- 필수 요구마다 확인 가능한 정상·경계·실패 사례를 고른다. 기존 도구/검사를 우선하고 구현을 복제한 테스트를 늘리지 않는다.
- 생성/계산은 작은 입력의 수동 기대값·단순 기준 해법과 대조한다. 원본 입력/설정과 최종 결과를 검사하며 공용 로직과 외부 가정을 밝힌다.
- **검사기 자체도 확인한다.** 규칙 하나를 고의로 위반한 작은 합성 결과를 넣어 잡는지 본다. 이런 변이/반례가 성공 데이터의 통과와 어떤 차이가 있는지 설명한다. 전면 변이 도구 설치는 필요할 때만 한다.
- 최적화/판정 기능은 유효성과 품질을 구분한다. 중요한 설정·분포 변화의 위반/미처리·평균/최대·실행 시간을 비교하고 미실행 예상은 가설로 둔다.
- 배경 작업은 해당되는 중복·실패·입력 변경·재시작을 허용된 격리 환경에서 확인한다. 서버 연결은 프로세스→포트/바인딩→Host/프록시→업무 경로 순서로 좁힌다.
- UI는 실제 허용된 검사만 수행한다. 정적 검색·빌드·HTTP 성공을 브라우저 동작이나 업무 정확성으로 확대하지 않는다. 플랫폼 설정/기록을 변경하지 않는다.

## 실패와 결과

재현 입력·기대/실제 결과→가설 하나→최소 수정→원래 사례/영향 사례 재확인의 순서로 좁힌다. 재현된 오류와 미검증 우려를 구분하고 실제 오류가 없다는 결론도 허용한다.

PASS / FAIL / TIMEOUT / ERROR / NOT_RUN / SKIP / HUMAN_CHECK를 근거에 맞게 표시한다. 예상한 오류 거절의 성공과 검사 자체의 실패를 구분한다. 재실행을 중복 합산하거나 생략된 사례를 통과로 쓰지 않는다.

`scripts/run_checks.py`는 명시한 argv 명령의 종료·시간·출력을 JSON으로 기록한다. 정확성/개수/업무 충족을 자동 판정하지 않는다. CSV 계약 검사에는 `scripts/check_submission.py --help`의 실제 옵션을 쓰고 예시 행 수·첫 열을 계약으로 추정하지 않는다.

새 변경/실패/구체적인 우려가 없으면 유효한 검사를 반복하지 않는다. 기록은 해당 테스트/기능의 현재 결과와 실제 사건만 갱신한다. 사용자와 합의한 변경 중단 후에는 기존 근거를 읽고 설명하며 자동 수정·새 장시간 검사를 시작하지 않는다.
