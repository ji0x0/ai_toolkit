# 기록 구획과 근거

관련 구획만 사용하고 문서 전체를 반복 생성하지 않는다. 기존 사용자 내용과 실제 실패 이력을 보존한다. 작성한 설명과 사용자가 직접 확인한 사실은 다르다.

## devlog — 실제 사건

```markdown
### 실제 시각/시간대 또는 확인한 경과 — 사건
- 목적·연결 기능/질문/결정:
- 변경 파일:함수·이유와 영향:
- AI 제안/가설·사용자 채택/수정 요청/기각·각 근거:
- 검사 목적·케이스/명령·입력·기대값/근거·실제 결과·판정:
- 코드/설정 변경 상태·환경·근거 위치:
- 사용자 직접 확인 범위 / 대기:
- 남은 한계·다음 행동:
```

사건이 없으면 새 항목을 만들지 않는다. 사후 정리는 근거와 함께 표시한다. 브리핑/수정/승인도 실제 사건이며 담당자 답변을 설계 승인으로 바꾸지 않는다.

## probe — 현재 문제와 선택

- 실제 사용자 역할·업무 목표/맥락·페인포인트·원인 근거/가설·해결 원리와 연결 기능.
- 질문/이유·실제 답변/출처·열린 항목·사용자 결정과 바뀐 규칙.
- 현재 계획/버전·기능/예외·설계/대안·검증/시간·사용자 실제 확인 범위.
- 기능별 요구→입출력→현재 파일/함수→채택한 기술/대안·장단점→선택 이유/포기한 점→검증/한계.
- 테스트 핵심 요약: 목적·입력·기대/실제값·판정·범위·SERVICE 상세/케이스/이력 위치.
- 기술 동작과 측정된 업무 효과, 사용자 이해 상태·남은 한계/다음 확인.

대안은 같은 기능을 실제로 만드는 방식으로 비교한다. 실제 비교 실행과 설계상 예상을 구분한다. 기능마다 중복되는 공통 결정은 한 번 기록하고 참조한다. 미사용 기술·없는 지표/협의/기각 사례를 만들지 않는다.

## SERVICE — 해당 서비스 상세

아키텍처·유스케이스/사용 흐름·화면/API 라우팅·모듈 계약·업무/운영 규칙·테스트 상세·읽는 지도는 이 문서를 정본으로 연결한다. build-service가 있으면 해당 스킬의 작성 기준/양식을 사용한다. 서비스가 아니면 해당 없음이다.

최적화의 목표/제약·독립 검사/고의 위반 검출·배경 작업 수명·조건 변화·환경 호환성은 실제 기능이 있을 때만 기록한다. 요약을 찾기 위해 세 문서를 전부 읽어야 하는 구조를 만들지 않고 probe의 해당 기능에서 상세 위치로 연결한다.

## 상태와 이해

PASS / FAIL / TIMEOUT / ERROR / NOT_RUN / SKIP / HUMAN_CHECK를 실제 근거로 구분한다. 미실행·생략·확인 대기를 통과로 합산하지 않고 재실행을 중복 집계하지 않는다. 변경 뒤 무관한 옛 결과를 최신 근거로 쓰지 않는다.

사용자 이해는 결과 예측→실제 코드/주석 추적→기존 검사 대조→본인 설명에서 확인한 범위만 적는다. AI가 설명/실행한 일을 사용자 수행으로 바꾸지 않는다. 변동 없는 턴에는 문서를 쓰지 않으며 변경 없는 이해 구간에는 짧은 확인 메모만 남긴다.
