# 업무의 현재 설명과 실제 이력

기록은 실제 업무 폴더에 둔다. 기존 파일/README·필수 협업 문서를 보존하고 실제 업무 자료를 공개 키트에 전송하지 않는다.

## 준비

설치/자동 세션은 devlog.md와 probe.md의 양식을 준비한다. 없으면 `python3 <스킬 경로>/scripts/init_records.py --root <업무 루트>`를 사용한다. 기존 파일·충돌을 덮어쓰지 않는다. 추가 파일이 금지되면 허용 문서의 구획으로 관리한다. 서비스 구현을 시작할 때 SERVICE.md를 준비한다. 빈 양식은 완료 근거가 아니다.

## 한 번 기록하고 필요한 곳만 연결

| 문서 | 관리하는 내용 | 갱신할 때 |
| --- | --- | --- |
| devlog.md | 실제 질의응답·결정·변경·실패/수정·실행 이력 | 새 사건이 있을 때 한 번 추가 |
| probe.md | 문제/사용자·원인 근거·선택/대안·기능/검증 핵심·한계 | 요구·선택·핵심 결과가 바뀔 때 해당 구획 |
| SERVICE.md | 현재 구조·계약·운영·테스트 상세·읽는 지도 | 서비스의 해당 구조/계약/결과가 바뀔 때 |

실제 시각·파일:함수·입력/기대값·관측·버전/변경 상태와 근거 위치를 연결한다. 긴 로그·설계를 세 문서에 복제하지 않는다. 변동 없는 설명 턴에는 기록을 다시 쓰지 않는다. 파일 감시의 해시/파일명 관측은 선택 이유나 테스트 성공을 대신하지 않는다.

브리핑/사용자 확인은 probe에 계획·범위·실제 답변으로, devlog에 사건으로 남긴다. 업무 답변 수신·내부 계획·시간 경과를 설계 승인으로 바꾸지 않는다. 같은 계획은 재승인받지 않는다.

[작성 양식](references/records.md)을 필요 구획에만 적용한다. 문제/페르소나·원인→해결→기능, 현실적인 대안·장단점·선택 이유·포기한 점을 실제 근거로 연결한다. 테스트는 목적·입력·기대/실제값·판정·범위를 쉬운 말로 설명한다. 없는 측정값·협의·AI 기각 사례·사용자 이해를 만들지 않는다.

AI 협업은 실제 증상/전달→가설/수정안→채택·수정 요청·기각과 근거→재확인을 기록한다. 사용자 직접 확인과 AI 실행을 구분한다. 필수 별도 협업 문서가 있으면 같은 사건을 그 의무 형식에 맞게 연결한다.

인계나 중대한 변경 뒤 기능·코드·검증·설명 정합을 한 번 대조한다. 변경 없는 이해 구간에서는 기존 자료로 설명하고 실제 이해 범위의 짧은 메모만 남긴다.
