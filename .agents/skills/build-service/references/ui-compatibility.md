# UI와 실행 환경의 호환성

화면 전환·외부 창·파일/권한 대화상자 등이 제한된 환경일 때 읽는다. 현재 사용 환경의 요구를 수용 조건에 반영하고 기존 플랫폼·접근 통제·기록 설정은 보존한다.

기본 UI는 같은 페이지의 컴포넌트/패널/탭으로 동작한다. 새 창/탭·최상위 이동/새로고침·인쇄·네이티브 창·자동 다운로드/클립보드 요청은 필요성과 허용 조건을 확인한 뒤 선택한다. 사용자/브라우저의 화면 모드를 앱이 임의로 바꾸거나 사용자 이탈을 막지 않는다. 필수 기능과 제약이 충돌하면 구현 전에 대안을 설명한다.

검토할 것은 실제 이벤트 경로다. 링크/폼의 의도치 않은 이동, `window.open`, `location`, `print`, 네이티브 대화상자·파일/클립보드·화면 모드 제어 API와 키 이벤트를 관련 UI에서 확인한다. 단순 문자열 검색만으로 호환성을 보증하지 않는다.

정상·실패·출력 흐름은 허용된 준비 환경에서만 확인한다. 제한된 운영 환경의 상태를 일부러 바꾸거나 허용되지 않은 자동화를 사용하지 않는다. SERVICE의 해당 구획에 코드/버전·동작·실제 환경 관측과 미확인을 남긴다. 빌드/HTTP 성공은 실제 UI 확인과 구분하며 브라우저/OS 동작을 앱이 절대 통제한다고 설명하지 않는다.
