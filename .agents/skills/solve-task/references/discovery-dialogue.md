# 문제와 담당자 답변 반영

README·기존 지침·제공 파일·대화에서 확인한 사실을 먼저 쓴다. 사용자 역할·업무 목표·현재 흐름·페인포인트·원인 근거·완료 기준을 연결하고 자료/담당자 설명/관측/가정을 구분한다. 근거 없는 인물 설정과 개선 수치를 만들지 않는다.

결과를 바꾸는 미확인 규칙만 우선순위로 질문한다. 각 질문은 그대로 보낼 문장·이유·답변에 따라 달라지는 구현/검증을 포함한다. 이미 자료/대화에 답이 있으면 재질문하지 않는다. 추천 기술에 동의하도록 유도하지 않는다.

담당자 확인이 필요하면 사용자가 실제 답변을 전달하도록 안내하고 그 부분을 기다린다. 별도 전송 지시가 없으면 대신 메시지를 보내지 않는다. 대기 중에는 독립적인 환경/자료 확인을 계속한다.

답변은 질문/출처에 연결하고 바뀐 규칙·열린 항목·충돌을 정리한다. 중요 정책이 미확인이면 해당 부분의 가정/대안을 사용자에게 설명한다. 답이 없는 업무 규칙을 확정하지 않는다.

필요한 답과 판단이 확보되면 [구현 전 브리핑](implementation-brief.md)으로 이어간다. 이미 브리핑/승인이 끝난 업무는 같은 대기를 반복하지 않는다. 시간과 이해 구간은 [현재 업무 일정](time-budget.md)에 따른다.

중간 질문은 사용자의 우선순위·정책·범위/중요한 시간·품질 절충에 한정한다. 추천·대안·장단점·영향과 대기 중 계속할 일을 설명한다. 파일명·함수 분리 등 통상 구현은 매번 묻지 않는다. 기록은 실제 답변/결정이 생긴 해당 구획만 갱신한다.
