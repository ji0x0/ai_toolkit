# 짧은 시작과 자동 세션

`$solve-task`만 입력하거나 “과제 시작해줘”라고 요청하면 기본 시작 흐름을 수행한다. 긴 시작 프롬프트를 다시 요구하지 않는다. 기존 과제·사용자 지침과 현재 AI 허용 단계가 우선한다.

## 시작

1. 실제 과제 루트, README·AGENTS, 제출물과 추가 문서 제한을 읽는다. 배포 키트 자체에는 적용하지 않는다.
2. 이 스킬의 `scripts/session.py start --root <실제 과제 루트>`를 실행한다. 기본 설치는 필요한 record-work와 git-checkpoint도 포함한다.
3. 응답의 `status=running`과 `last_snapshot.status=saved|unchanged`, 스냅샷 위치를 확인한다. 시작 오류·중단·파일 제외를 숨기지 않는다. 환경에서 백그라운드 실행이 차단되면 우회하지 않고 사용자에게 미작동 상태를 알리고 플랫폼 문의로 연결한다.
4. record-work의 작성 기준을 읽고 devlog.md의 현재 상태와 probe.md의 요구·기능 목록을 실제 과제 내용으로 채운다. 형식만 생성한 상태로 분석 완료라고 하지 않는다.
5. 요구 분석→필요한 뼈대 선택→구현→대표 검증→코드 이해 인계로 이어간다. 기본 인계 목표는 T+60분, 지연 시 T+80분이다. 실제 과제 시작 시각을 확인하고 세션 시작 시각과 혼동하지 않는다.

별도 사용자 설정 없이 180초마다, 최대 10800초 동안 로컬 스냅샷을 남긴다. 소스·설정·문서 경로는 매번 다시 발견하므로 새 폴더도 포함한다. 중복 호출은 실행 중인 세션을 재사용한다. Git 작업 트리 루트면 Git 메타데이터 안에 저장하며, 아니면 `.local/ai-toolkit/snapshots/`를 사용한다. Git 초기화·자동 stage/commit/push는 하지 않는다.

풀이의 실제 남은 시간이 확인되면 `--duration <남은 초, 최대 10800>`으로 더 짧게 제한한다. 알 수 없는 시험 타이머를 임의로 읽었다고 가정하지 않는다. 만료 시각과 별개로 제출물 확정 전 stop을 수행한다.

기본 자동 선택은 CSV, 비밀 파일명, 숨김 도구 폴더, 생성물·의존성·바이너리·크기 초과 파일을 제외한다. CSV와 대용량 데이터는 별도 저장 계약을 따른다. 이름 필터는 모든 비밀정보를 찾아내는 도구가 아니다. 제외 항목은 status에서 확인하고 필요하면 선택형 checkpoint 도구를 사용한다.

## 기록 갱신: 별도 호출을 요구하지 않는다

- 요구·범위 확정 뒤: devlog에 실제 확인·가정·질문, probe에 요구/기능과 수용 기준.
- 기술 선택·구현 변경 뒤: devlog에 목적·변경·실패/수정, probe에 코드 위치·선택 도구·현실적 대안·각 장단점·선택 결론·한계.
- 검증 뒤: devlog에 실제 명령·결과·근거, probe의 해당 기능에 기대값/실제값·통과/실패·미검증 범위.
- 사용자에게 코드 인계하거나 작업 턴을 마치기 전: 기능 목록↔코드↔검증↔문서의 누락을 대조하고 변경한 기능만 갱신한다. 사용자 이해는 확인 전까지 대기다.
- 긴 실행 중에는 의미 있는 경계에서 갱신한다. 매 도구 호출마다 문서를 쓰거나 같은 내용을 반복해 구현 시간을 소모하지 않는다.

파일 감시 도구는 devlog에 관측된 파일명·해시 변화만 자동 추가한다. 변경 의도·테스트 성공·기술 선택 이유를 추정하지 않는다. 이 의미 있는 설명과 probe의 현행 갱신은 **현재 작업을 수행하는 Codex의 책임**이다. 감시 도구는 모델을 호출하지 않으며 추가 토큰을 소비하지 않는다.

## 유지·종료

인계와 세션 재개 시 `scripts/session.py status --root <과제 루트>`로 실제 실행을 확인한다. `interrupted`이면 마지막 사본과 현재 파일을 비교한 뒤 필요한 경우 start로 재시작한다. 설치만으로 실행되었다고 주장하지 않는다.

제출물 확정 **전에** `scripts/session.py stop --root <과제 루트>`로 최종 스냅샷과 종료를 확인한다. 이후 AI 금지 단계에서는 이 흐름을 수행하지 않는다. 사용자가 “자동저장 끄기”라고 요청해도 같은 stop을 사용한다. 관련 없는 프로세스는 종료하지 않는다.

추가 기록 파일이 금지되면 `start --no-records`로 실행하고 허용 문서에 해당 내용을 유지한다. 자동저장 금지·추가 파일 금지 등 명시된 운영 제약이나 사용자의 해제 요청이 있으면 해당 자동 동작을 수행하지 않는다. 에디터 미저장 버퍼와 프로세스는 스냅샷으로 복구되지 않는다.
