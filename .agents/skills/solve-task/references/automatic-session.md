# 기록 준비와 로컬 자동저장

실제 업무 루트·지침·추가 파일/도구 제한을 확인한 뒤 `scripts/session.py start --root <업무 루트>`를 실행한다. 설치가 제한된 참조 모드는 bootstrap이 반환한 session_script/스킬 경로를 사용한다. 관리 폴더의 권한을 바꾸지 않는다.

응답의 `status=running`, `last_snapshot.status=saved|unchanged`와 실제 저장 위치를 확인한다. 실패/중단/제외 항목을 숨기지 않는다. 상태 확인은 `status`, 종료는 `stop` 하위 명령이다. 인계/종료 전에 최종 사본과 종료 상태를 확인한다.

- 기본은 정해진 간격으로 유한 시간 동안 로컬 사본을 저장한다. 실제 간격/기간은 `start --help`로 확인하며 필요한 경우 지정한다. 프로세스 상한은 업무 마감이 아니다.
- Git 없이도 업무의 `.local/ai-toolkit/snapshots/`를 사용하고 Git 초기화·stage/commit/push를 하지 않는다. 반복 시작은 실행 중 세션을 재사용한다.
- 새 소스 폴더도 수집하지만 CSV·비밀 파일명·숨김 도구·의존성·생성물·바이너리·크기 초과는 기본 제외한다. 원본 데이터 저장 계약을 별도로 확인한다. 미저장 에디터 버퍼/프로세스는 복구하지 못한다.
- 기록 금지면 `--no-records`, 자동저장 자체 금지면 실행하지 않는다. 일반 작업 쓰기/백그라운드 실행이 차단되면 실제 오류를 알리고 우회하지 않는다.

업무 흐름은 문제/답변→브리핑/확인→구현/검증→이해/인계다. 시간 경계는 [합의 일정](time-budget.md)을 따르며 감시 시작/재시작이 업무 시작을 바꾸지 않는다.

`record-work`는 실제 요구/결정/변경/검사 사건에만 해당 문서 구획을 갱신한다. 같은 내용을 세 문서에 복제하거나 변동 없는 턴마다 다시 쓰지 않는다. 감시 도구의 파일명/해시 관측은 판단·테스트 성공을 추정하지 않으며 모델을 추가 호출하지 않는다.
