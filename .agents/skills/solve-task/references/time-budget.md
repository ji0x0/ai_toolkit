# 업무별 시간과 이해 구간 합의

현재 사용자 지시·업무 안내에서 실제 시작/마감, 첫 인계, 보완 종료(변경 중단), 변경 없는 이해 구간의 시작/끝을 확인한다. 지정되지 않은 시각이나 총기간을 만들지 말고 범위·실행 비용을 근거로 제안해 합의한다. 개인 시간표를 공개 기본값으로 고정하지 않는다.

| 구간 | 할 일 | 종료 기준 |
| --- | --- | --- |
| 문제 분석·1차 구현 | 질문/답변·상세 브리핑 확인·필수 경로·대표 검증 | 동작·검증 근거·읽을 코드/자료 첫 인계 |
| 보완과 이해 병행 | 승인 범위 수정·영향 검사·주석/문서 정합·사용자 확인 | 합의한 변경 중단 시점까지 준비 완료 |
| 변경 없는 이해 | 입력 예측·코드 추적·선택 이유·기존 검사 결과·본인 설명 | 현재 버전의 이해 범위와 남은 질문 확인 |

첫 인계가 늦어져도 마지막 이해 구간을 임의로 개발에 쓰지 않는다. 원인·현재 상태·줄일 범위와 남은 보완 시간을 알린다. 사용자 확인/담당자 응답 대기도 실제 경과에 포함하며 답변·감시 재시작 시 시계를 다시 시작하지 않는다.

새 구현/수정은 짧은 자료 확인 뒤 예상 범위와 근거·미확인, 구현/검증/기록 배분·인계 영향을 먼저 알린다. 단순 설명마다 견적을 반복하지 않는다. 범위/오류/첫 실행 비용이 달라질 때만 남은 시간을 갱신한다.

변경 중단 뒤에는 새 기능·리팩터링·자동 오류 수정·장시간 검사/문서 확장을 멈춘다. 짧은 이해 메모 외에는 기존 자료를 사용한다. 수정은 사용자 명시 요청과 이해 시간 영향 설명이 있을 때 요청 범위만 수행한다.

필수 실행/저장/인계 준비도 변경 중단 전에 마친다. 별도 마무리 절차는 현재 안내의 시간/자료/도구 조건을 확인한다. 자동저장 프로세스의 유한 실행 한도는 업무 마감과 구분한다.
