# 업무 범위·견적·검토 시간을 반영한 일정 계획

업무의 목표·범위·의존성·마감·담당자 응답 가능 시간에 맞춰 일정을 제안한다. 이전 업무의 전체 시간이나 고정 인계 시점을 새 업무에 적용하지 않는다. 마감이 정해지지 않았다면 확인된 범위의 예상 소요와 전제를 제시하고 필요한 검토 시점을 협의한다.

## 요청을 받았을 때 예상 시간 안내

- 새 업무 또는 추가 구현·수정 요청의 관련 파일·실행 환경·현재 상태를 짧게 확인하고 작업 전에 예상 소요 범위를 알린다. 단순 설명·확인 질문마다 시간을 붙이지 않는다.
- 요구 확인, 상세 브리핑·계획 수정, 설치/설정, 구현, 검증·기록, 담당자 인계·사용자 리뷰 시간을 구분한다. 담당자 답변/계획 확인 대기가 미정이면 별도로 표시하고 실제 경과시간에는 포함한다.
- 지금부터 남은 예상 소요, 실제로 확인한 업무 경과시간, 예상 인계 시점을 구분한다. 시작 시각을 확인할 수 없으면 임의 T+나 완료 시각을 만들지 않는다.
- 예상 시간의 근거와 불확실성, 외부 의존성·권한·데이터·실행 비용을 밝힌다. 정밀한 단일 숫자를 보장하는 대신 범위와 재확인 시점을 제시한다.
- 추가 요청이 기존 기능·품질·인계 일정·리뷰 시간에 주는 영향을 설명한다. 중요한 범위 선택은 대안·추천과 함께 사용자에게 확인하고 기존에 합의한 같은 범위의 승인은 반복하지 않는다.

안내 형식: **예상 X~Y분/시간(브리핑·구현·검증/기록 배분). 전제·미확인 조건. 담당자 확인 대기. 제안 인계/리뷰 시점과 현재 마감에 미치는 영향.** 단위와 값은 실제 업무 규모에 맞춰 쓴다.

## 단계별 계획과 완료 기준

| 단계 | 할 일 | 다음 단계로 갈 근거 |
| --- | --- | --- |
| 요구·환경 파악 | 사용자/업무 흐름·목표·자료·기존 코드·운영 제약·산출물 확인 | 확인한 사실·수용 기준·열린 질문 |
| 담당자 협의 | 결과를 바꾸는 질문과 답변·충돌·우선순위 반영 | 업무 규칙과 범위의 근거 |
| 상세 브리핑·계획 확인 | 결과물·사용 흐름·설계/대안·위험/검증·일정 설명 | 제시한 계획에 대한 사용자 확인 |
| 핵심 경로 구현 | 합의한 범위의 작은 작동 경로부터 연결 | 실제 입력→업무 처리→출력과 대표 검증 |
| 검토·수정 | 코드/문서·정상/경계/실패·운영 조건 확인 | 확인된 오류와 미검증 위험·필수 수정 결과 |
| 설명·업무 인계 | 구조·선택 이유·실행/운영·근거·남은 항목 공유 | 담당자가 사용할 수 있는 산출물과 확인 범위 |
| 후속 작업 | 운영 결과·새 요구·미해결 사항 반영 | 새 범위/일정·필요한 계획 변경 확인 |

이 표는 단계별 기준이며 단계마다 고정 시간을 부여하지 않는다. 사용자가 구체적인 시간 한도를 지정하면 그 안에서 구현·리뷰·검증·인계를 배분한다. 짧은 업무에도 필요한 브리핑을 생략하지 않되 규모에 맞는 깊이로 설명한다.

## 진행 중 재추정

담당자 답변 수신, 범위/의존성 변경, 첫 실제 실행, 오류나 운영 조건 변화 시 남은 작업과 예상 시간을 갱신한다. 지연 원인·현재 완료 범위·남은 검증·마감 영향·가능한 범위 조정을 짧게 알리고 중요한 변화는 devlog.md에 남긴다.

답변 대기가 길어지면 독립적인 읽기 전용 점검과 기록을 진행한다. 답변이나 계획 확인을 추정하지 않으며 사용자 확인 전 업무 구현을 시작하지 않는다. 인계 목표를 맞추려고 미완성·미검증을 완료로 표시하지 않는다.

## 실행과 리뷰 시간 확보

실제 실행 시간을 측정해 재실행·회귀 검사·인계 전에 필요한 여유를 계획한다. 전체 실행을 마감 전에 끝낼 수 없으면 확인한 대표 범위와 NOT_RUN 범위, 사용자 영향을 구분한다. 측정하지 않은 실행 시간을 단정하지 않는다.

사용자가 코드를 읽거나 담당자가 검토하는 동안은 설명·재현·합의한 오류 수정에 집중한다. 중요한 변경은 위치·이유·영향을 먼저 알리고 이전 버전과 현재 버전의 차이를 확인한다.

## 세션과 업무 마감의 구분

자동저장 도구의 최대 10800초는 백그라운드 감시의 안전 상한이며 업무 완료 시한이 아니다. 필요한 저장 기간을 명시하고 만료 뒤에는 상태와 필요를 확인해 다시 시작할 수 있다. 업무 세션 종료나 사용자 요청 시 최종 사본과 감시 종료를 확인한다. 인계 후 변경은 합의한 후속 범위와 버전/검증 기록으로 관리한다.
