# 현재 코드를 본인이 설명할 수 있게 인계

실제 파일/실행 결과와 SERVICE·probe·devlog의 해당 구획만 읽는다. 사용자 역할·페인포인트·원인/근거→현재 기능→선택 이유/대안→검증과 한계를 연결한다. 기술 이름·폴더 목록만 나열하지 않는다.

## 대표 입력 하나씩 추적

1. 사용자가 하려는 행동과 화면/파일 결과를 설명하고 작은 입력의 결과를 먼저 예상하게 한다.
2. 실제 UI 이벤트→API/서버 진입점→핵심 함수/분기→검증·저장→응답/표시를 따라간다. 중간 값·단위를 함께 읽는다.
3. 상세 한국어 주석과 읽는 지도로 설명한다. 변수·타입·반환값·상태·await 등 처음 보는 문법을 쉬운 말로 풀고 막히는 구문은 줄별로 다룬다.
4. 테스트의 준비 입력→호출→기대값 비교(assert)와 실제 결과를 읽는다. 어떤 규칙을 왜 검사했고 무엇은 확인하지 못했는지 설명한다.
5. 사용자가 선택 이유·규칙·결과·한계를 자신의 말로 설명한다. 실제 확인한 이해 범위만 기록한다.

아키텍처 관계, 유스케이스/사용 흐름, 화면/API 라우팅, 모듈 입출력 계약을 현재 코드로 연결한다. 최적화의 목표/제약·얻고 포기한 점, 배경 작업의 중복/실패/재시작, 조건 변화는 해당 기능일 때 다룬다. AI 협업 판단은 실제 이력으로 설명한다.

주석·설명 자료와 관련 검증은 합의한 변경 중단 전까지 준비한다. 이후에는 코드/설정/테스트 변경·문서 확장 없이 현재 코드로 이해만 지원한다. 발견한 문제는 수정 후보로 남기고, 사용자의 명시 수정 요청이 있으면 이해 시간 영향을 설명한 뒤 요청 범위만 다룬다.

같은 계획/범위의 작업은 재승인받지 않는다. 구현 전 브리핑은 예정 동작임을 밝히고 사용자가 새 계획을 확인한 뒤 진행한다. 사용자 설명/실행이 없으면 이해 완료·직접 검증이라고 쓰지 않는다.
